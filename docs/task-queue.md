# 持久化任务队列

## 运行方式

任务输入、状态、尝试次数、租约和错误保存在 `app/data/events.sqlite3` 的 `jobs` 表中；账号仍在 `accounts.sqlite3`，不增加第三份数据库。独立 worker 领取任务，每次尝试启动单独执行进程，API 只负责入队、权限校验和进度推送。

默认启动 API 后自动启动独立 worker，worker 意外退出时 API 会再次拉起：

```powershell
uv run uvicorn app.api.server:app --host 0.0.0.0 --port 8000 --reload
```

运行在 Windows 时，自动 worker 使用隐藏窗口，执行进程采用 `spawn`。前端启动方法保持不变。

生产环境可在 `.env` 设置 `TASK_QUEUE_AUTOSTART=0`，重启 API，再在另一终端运行：

```powershell
uv run python -m app.worker
```

两个进程需使用同一项目目录和同一数据库；自定义数据库可通过 worker 的 `--db 路径` 指定，但 API 必须访问同一文件。生产环境应使用进程管理器守护独立 worker。独立 worker 正常运行时，重启 API 不会停止执行；自动模式下 worker 随 API 停止，未完成尝试会进入故障恢复。

## 配置

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `TASK_QUEUE_AUTOSTART` | `1` | API 自动管理 worker；设 `0` 时需单独启动 |
| `TASK_QUEUE_CONCURRENCY` | `2` | 同一数据库最多同时执行的任务数，范围 1–16 |
| `TASK_QUEUE_TIMEOUT_SECONDS` | `600` | 每次尝试的进程时限，范围 1–86400 秒，含 Agent 启动时间 |
| `TASK_QUEUE_MAX_RETRIES` | `3` | 首次尝试之外的自动重试次数，范围 0–10 |
| `TASK_QUEUE_RETRY_DELAY_SECONDS` | `2` | 指数退避基数，默认等待 2、4、8 秒，单次最多 60 秒 |
| `TASK_QUEUE_LEASE_SECONDS` | `15` | 心跳租约，范围 3–300 秒，约每租期三分之一续约 |

超时和重试次数在入队时记录，修改后影响新任务；worker 并发、租约和退避设置需重启生效。同一队列的 worker 应使用一致配置。

## 状态和行为

`queued → running → succeeded`；执行失败进入 `retry_wait`，到期后重新领取；预算耗尽进入 `failed`。默认首次尝试加 3 次重试，最多执行 4 次。排队任务按入队先后领取，尚未到重试时间的任务不会阻塞其他已就绪任务。

- **入队**：任务和 `task_queued` 事件在同一 SQLite 事务提交；同一会话最多存在一个活跃任务，重复提交返回 HTTP 409。
- **并发**：使用数据库写事务原子领取，多个 worker 不会同时领取同一任务，并检查数据库中全局运行数量。
- **重试**：执行异常、进程崩溃和硬超时按预算重试；失败信息保留，重试不会在历史中伪造一条新的用户问题。
- **硬超时**：父 worker 到时终止执行进程，必要时强制 kill，并确认进程停止后再更改状态；不能只取消等待而放任线程继续执行。
- **恢复**：worker 心跳停止后，其他 worker 或 API 启动检查会将过期任务重新安排。崩溃前的尝试计入预算，不无限重置次数。子进程也检查租约，父进程丢失后会退出。
- **过期消息隔离**：每次领取生成独立令牌；状态变更和旧尝试事件写入都检查令牌，防止晚到消息覆盖新尝试。
- **取消**：排队或等待重试的任务立即取消；运行中先标记 `cancelling`，由 worker 终止进程后确认 `cancelled`；已取消任务不自动恢复。
- **手动重试**：前端失败状态显示“重试任务”，将最后一个失败任务以新 job 入队，保留之前的失败记录。
- **进度**：API 读取独立 worker 写入的事件，按 ID 推送并去重；刷新后恢复队列状态，前端显示排队、执行、等待重试及取消状态。
- **对话上下文**：每次执行进程从已完成的对话事件重建用户/助手消息，兼容升级前的已完成历史；不恢复工具中间状态。

## API 与权限

| 接口 | 用途 |
| --- | --- |
| `POST /api/task` | 入队，返回 `status=queued`、`thread_id`、`job_id` |
| `GET /api/task/{thread_id}` | 本会话最新状态、排队位置、尝试次数及错误 |
| `POST /api/task/{thread_id}/cancel` | 取消排队或执行任务 |
| `POST /api/task/{thread_id}/retry` | 将最新失败任务重新入队，非失败状态返回 409 |

上述接口及 WebSocket 均校验登录身份和会话所有者，不允许跨用户查询、取消或重试。

## 恢复边界

这是同一主机、本地 SQLite 磁盘上的持久化队列，不是 Redis/Celery，也不是多服务器分布式队列。不建议将数据库放到网络共享盘。

恢复语义是**至少一次尝试**，不是恰好一次，也不是 Agent 断点续跑。重试可能重复付费模型调用、搜索和文件生成，部分文件可能遗留或被覆盖。用户应以成功状态下的结果为准；将来增加外部写操作时，必须单独设计幂等性。当前任务记录保存问题并使用会话现有附件，不是附件内容快照。

队列自动重试和 SQL 工具内部重试是两层独立预算；新执行进程会重新初始化本次尝试的 SQL 工具预算。进程关闭、启动和轮询可能产生少量延迟，时限不是严格实时保证。

升级前没有队列记录的进行中任务无法补回输入，仍标记中断；旧历史保留。重试无法恢复已删除附件或丢失的数据库。备份应协调停止 worker 后同时保存账号库、事件/队列库及会话文件，不要只复制正在写入的 SQLite 主文件而遗漏 WAL。

## 测试与手动验收

```powershell
uv run python -m unittest discover -s tests -p 'test_*.py'
node tests/test_history.cjs
node tests/test_scroll_follow.cjs
npm.cmd --prefix frontend run build
```

自动测试使用真实 SQLite 和实际 `spawn` 子进程，但模型执行替换为测试任务，不调用外部模型。覆盖原子入队、FIFO、并发竞争、重试上限、租约恢复、过期写入拒绝、超时 kill、取消、跨进程 WebSocket 推送、重启保留和用户隔离。

手动验收：将并发设为 1，在两个不同会话提交问题，观察后一项排队；取消排队项；刷新执行中的页面；以独立 worker 模式测试 API 重启；停止 worker 后重新启动，观察失联任务在租约和退避时间后重试。真实模型的费用和失败情况不属于离线测试结果。
