# 2026-10-19 RAGFlow 调用问题定位与解决

## 问题与最终结论

用户反馈 RAGFlow 助手无法调用。检查工具封装后补充了接口兼容、错误识别和异常清理；诊断过程中又发现测试命令自身存在中文编码丢失。

最终复测：保留正确中文后，真实知识库检索返回片段，修复后的 `create_ask_delete` 工具成功返回回答。不能将此次诊断中的断言当作模型配置错误或索引损坏的证据，无需据此重建知识库。用户网页中的完整调用流程仍需重启本项目后端后复测。

## 定位过程与误判纠正

1. 助手列表接口返回 HTTP 200、业务码 0，可见 2 个助手；两个知识库分别已有 142、241 个片段。
2. 首次诊断提问收到 HTTP 200，但 SSE 内含业务码 500、空错误信息及 `**ERROR**: `。独立检索也返回业务码 100、`AssertionError()`，当时误判为服务端检索故障。
3. 用户提供腾讯云 Docker 日志，完整堆栈定位到 `/ragflow/rag/utils/es_conn.py:197`，即检索表达式类型和数量的断言。
4. 对比输入后发现，Windows PowerShell 管道将传给 Python 的中文测试问题变成纯问号。这批诊断请求触发了断言，不能据此认定模型或索引故障。
5. 使用 Python Unicode 转义保留中文后，检索和工具问答成功；已明确向用户纠正之前的判断。

经验：检查接口时也要确认实际发送的文本；HTTP 200 不代表业务成功，模拟测试也不能代替真实调用。

## 解决方法与修改位置

| 文件及函数 | 原问题 | 处理方式 |
| --- | --- | --- |
| `app/tools/ragflow_tools.py` `_request` | 模块级客户端、请求缺少超时 | 工具调用时加载配置，设置连接和读取超时 |
| 同上 `_list_chats` | 响应格式和描述字段存在版本差异 | 兼容列表及 `data.chats`，处理空描述，支持分页 |
| 同上 `create_ask_delete` | 固定旧版路径，名称缺失时可能索引越界 | 优先新版路径，同时传 `messages` 和 `question`；仅 HTTP 404/405 回退旧路径；明确报告缺失或同名助手 |
| 同上 `_read_answer` | 忽略 SSE 业务错误，可能输出空结果或错误文本 | 检查 HTTP 和业务码，识别 JSON 错误、空回答及错误答案；明确请求累计回答避免重复拼接 |
| 同上 `create_ask_delete` | 异常路径不删除临时会话 | 使用 `finally` 清理，清理失败不覆盖原始结果 |
| 同上 `create_ask_delete` | 纯问号等无有效检索文字的输入触发远端断言 | 提交前检查是否包含文字或数字；该检查不能识别所有乱码 |
| `app/ragflow/rag_config.py` `_load_ragflow_env` | 缺失或不规范配置缺少明确反馈 | 校验 Key 和 URL，规范化末尾 `/api/v1`，读取项目 `.env` |
| `tests/test_ragflow_tools.py` | 缺少协议及错误路径测试 | 新增 9 项测试，覆盖兼容、超时、业务错误、清理和损坏输入 |
