# 四类任务的评测体系

## 问题现象

已有功能回归测试，但缺少统一任务集、业务质量评分与报告入口，难以比较搜索、自然语言数据库查询、知识库回答和文件生成能力的变更效果。

## 定位证据

检查现有搜索、MySQL、RAGFlow、Markdown/PDF 工具、模型初始化和 tests 目录，确认可以复用实际工具调用；仅将现有单元测试通过率当成真实服务质量会混淆两种验证目的。因此分别实现离线评分回归与在线真实服务评测，报告明确模式。

## 解决方法与修改位置

- `evaluations/tasks.json`：四类各 3 项，共 12 个起始任务，带阈值、相关网页、参考 SQL、回答事实/禁止表述、文件内容要求及离线样本。
- `evaluations/scoring.py`：搜索 Precision@K / Recall@K / MRR / nDCG；SQL CSV 结果匹配（列名、排序、重复记录、十进制值）；知识库事实覆盖与禁止表述；文件生成成功率。
- `evaluations/run.py`：离线/在线模式、按类别筛选、任务校验、单项进程硬超时、独立文件目录、JSON/Markdown 报告、同模式/同任务集基线比较、失败非零退出码。关键逻辑添加中文注释。
- 在线 SQL 将问题与样例表结构发给项目模型，参考 SQL 不发给模型；候选与参考分别经项目 SQL 工具执行，不绕过只读和白名单限制。
- `evaluations/knowledge.md`：专用知识库基准资料，含明确事实与未知信息；通过 `EVAL_RAGFLOW_CHAT_NAME` 指定专用助手。
- `tests/test_evaluations.py`：新增 10 项回归，包含在线分发的替代调用、参考答案隔离、评分负例、进程超时、文件缺失内容、非法任务和基线不兼容。
- `.env.example`、`.gitignore`、`README.md`、`docs/evaluation.md`：补充配置模板、忽略默认评测产物、功能入口和使用/评分边界说明。

## 验证结果

- 完整后端测试：`python -m unittest discover -s tests -p 'test_*.py'`，61 项通过。
- 离线评测：12/12 通过，搜索/SQL/RAG 使用固定样本；文件工具实际生成 1 份 Markdown 和 2 份 PDF，读取文件并检查要求文本。
- 再次执行离线评测并指定前次报告作为基线：12/12 通过，四类通过率变化均为 0，报告生成成功。
- 在线适配测试使用替代模型及工具，不代表已调用真实外部服务；本次没有执行付费模型、Tavily 或 RAGFlow 在线质量评测。

## 遗留问题与解释边界

- 起始任务集规模较小，需要持续加入业务代表性任务和已发现的失败案例。
- 评测覆盖工具与模型链路，不覆盖主智能体完整调度、浏览器或队列端到端行为；SQL 使用仓库样例表结构。
- 离线 SQL fixture 是评分器的小样本，不能作为实际查到销售表 40 行的证据。
- 知识库词语匹配仅是代理指标，不等同于语义忠实度或引用真实性；正式使用需人工抽查。搜索标注需维护，SQL 对比时应避免业务数据同时变更。
- 文件指标验证生成、可解析和文本内容，不评价视觉排版。强制超时可能打断 RAGFlow 临时会话清理。
- 默认报告忽略提交，报告不含业务回答或 SQL 明细；本次报告保留在本地 `evaluations/reports/`。

## 同日追加：扩充并拆分任务集

### 问题与定位

初始每类仅 3 项，覆盖面有限，也不方便用独立文件管理不同类别。检查现有 CLI 后确认 `--tasks` 已支持选择独立任务集，无需修改运行器或增加先离线再在线的前置条件。

### 解决方法与修改位置

- `evaluations/tasks.json` 从 12 项扩充到 32 项，四类各 8 项。搜索加入 5 个已核对地址的 Python 官方文档问题；SQL 加入库存排序、中文筛选、JOIN、HAVING 和空结果；RAG 加入存储、刷新、归属、查询策略、并发与超时；文件加入中文、列表、代码块和长文档。
- `evaluations/suites/` 新增 `smoke.json`（原始 12 项）及 `search.json`、`sql.json`、`rag.json`、`file.json`（各 8 项），均通过已有 `--tasks` 参数使用。
- `evaluations/knowledge.md` 补充新增 RAG 问题对应基准事实；在线使用前需重新导入解析。
- `tests/test_evaluations.py` 新增带中文说明的数据一致性检查，验证分类任务与默认集同步、快速集为默认集子集、参考 SQL 符合策略、非文件离线样本满足阈值。
- `README.md`、`docs/evaluation.md` 同步数量、分类命令和基线变化说明。

### 验证结果与限制

- 默认集离线运行：32/32 通过；8 个文件任务先生成 8 份 Markdown，其中 5 项再转换并解析验证 PDF（另外 3 项仅验证 Markdown），包含中文和长文档，长文档 PDF 为 5 页。搜索新增样本把相关结果放在第二位，评分约 0.631，验证非满分排序场景仍可按阈值判定。
- 评测专项回归：11 项通过；没有重复执行其他未受影响的应用测试。
- 新增网页标注已访问官方页面核对，但未执行 Tavily、模型/MySQL 或 RAGFlow 在线质量评测。离线通过不能视作线上质量结论，PDF 未做视觉排版验收。
- 默认集变化后旧报告哈希不兼容，需建立新基线；快速集保留旧题目，但其 JSON 文件也应单独建立对应基线。
