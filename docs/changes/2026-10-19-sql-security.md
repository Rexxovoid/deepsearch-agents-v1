# 2026-10-19 SQL 安全、查询超时与重试上限

## 问题

原数据库工具直接拼接预览表名、执行模型原始 SQL，连接使用自动提交，仅靠提示词要求只读；没有白名单、查询时限或自动重试上限。

## 解决方法与修改位置

- `app/tools/sql_safety.py`：新增 SQLGlot AST 校验、白名单配置、函数批准集合及输出行数限制；解析所有作用域中的真实表，区分 CTE 别名；执行重新生成的 SQL。
- `app/tools/db_tools.py`：统一三个工具的白名单与错误处理，核验基础表类型，开启只读事务，设置 MySQL 执行/锁等待及驱动网络超时；禁用多语句和本地文件导入；仅为暂时性故障最多重试 3 次。
- `app/agent/main_agent.py`：每次研搜创建并释放共享重试预算，防止模型重复调用工具重置次数。
- `app/prompt/prompts.yml`：说明只读、白名单及收到 `SQL_RETRY_EXHAUSTED` 后停止 SQL 访问的规则。
- `.env.example`：新增白名单、查询时限和最大结果行数配置。
- `pyproject.toml`、`requirements.txt`、`uv.lock`：新增 SQLGlot，将 Connector/Python 最低版本提升至支持读写超时的 9.2.0；本地安装 SQLGlot 30.23.0。
- `tests/test_sql_safety.py`：新增安全校验、执行约束和重试预算测试。
- `docs/sql-security.md`、`README.md`、`docs/changes/update.md`：使用方式、限制与更新记录。

## 开发中遇到的问题

1. 只判断 SQL 开头是否为 SELECT 无法阻止子查询越权、文件导出或有副作用函数；改用作用域分析、危险节点拒绝及函数批准集合。
2. 初次解析器配置使用字符串 `"RAISE"`，未对部分不完整 SQL 抛错；改为 SQLGlot 的 `ErrorLevel.RAISE` 枚举，并测试不完整 WHERE 在连接数据库前被拒绝。
3. 只在单次工具调用内计数，模型可以反复调用以绕过上限；将可变预算通过 ContextVar 在同一任务及其工具工作线程中共享，新任务重置。
4. 初次多表 COUNT 查询被优化或很快完成，不能证明超时中断有效；改用递归 CTE 构造只读计算查询，以 1 秒服务器时限验证，MySQL 在约 1.08 秒返回错误码 3024。
5. 视图虽然可以 SELECT，却可能读取白名单之外的数据；工具只接纳 `BASE TABLE`，视图不作为白名单可执行对象。

## 验证与限制

- 本地 MySQL 列出 `drugs`、`inventory`、`sales_records`，SELECT 读取 2 行成功；超时验证返回 3024。
- 自动测试覆盖写入、多语句、注释、导出、锁、变量、危险函数、跨库/非白名单访问、CTE 遮蔽、视图、重试停止、跨线程预算及只读初始化失败。
- 最终 32 项后端测试全部通过，其中本次新增 15 项 SQL 测试；前端历史恢复测试和 `uv lock --check` 通过，`git diff --check` 无空白错误。
- 重试语义为首次执行加最多 3 次重试；超时和临时连接故障才消耗预算，永久错误不重试。单次任务共享预算，独立脚本按调用计数。
- 本次没有修改数据库授权；应结合仅有白名单表 SELECT 权限的专用账号部署。未实现行级或字段级隔离。
- 功能需要更新依赖并重启后端，不修改或上传用户 `.env`。
