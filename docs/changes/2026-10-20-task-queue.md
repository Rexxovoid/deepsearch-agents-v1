# 2026-10-20 持久化任务队列、超时与故障恢复

## 问题与证据

原 `POST /api/task` 在 API 内创建 asyncio.Task，以 `active_tasks` 内存字典保存状态；重启会丢失执行对象，只能给历史添加中断提示。无限制立即执行也不能排队、隔离卡住的同步调用或可靠重试。

## 实现与修改位置

- `app/task_queue.py`：在现有事件库创建 jobs 表，原子入队和状态/事件提交；唯一活跃会话约束、FIFO 领取、全局并发上限、重试退避、心跳租约、取消及过期尝试令牌隔离。
- `app/worker.py`：独立 worker 命令，每次尝试用 Windows 兼容的 spawn 子进程；硬超时和取消真正终止执行进程；父 worker 崩溃时子进程通过租约看门狗退出。
- `app/api/server.py`：HTTP 只入队，增加状态和失败重试接口；API 自动管理 worker，可配置外置 worker；读取跨进程事件并推送。
- `app/api/monitor.py`、`app/api/event_store.py`：事件增量读取和每连接 ID 水位，避免历史回放和实时推送重复。
- `app/agent/main_agent.py`：队列托管模式抛出异常交由 worker 处理；新进程从已完成历史恢复对话消息，工具中间状态不恢复。
- 前端 `types.ts`、`lib/api.ts`、`lib/history.ts`、`hooks/useDeepAgentSession.ts`、`App.tsx`、`ConversationThread.tsx`：排队/重试状态、刷新恢复和手动重试；自动重试仍属于同一轮，人工重试新增轮次。
- `.env.example`、`README.md`、`frontend/README.md`、`docs/event-persistence.md`、`docs/task-queue.md`：参数、启动、备份和恢复边界；不新增第三份数据库。

## 开发中遇到的问题与处理

1. 仅将任务包装到 asyncio 队列仍会在进程重启时丢失，且取消协程不能停止阻塞线程；改为 SQLite 持久化队列及独立执行进程。
2. worker 直接推送不了 API 中的 WebSocket；通过数据库事件流桥接，结合连接水位去重，测试真实独立子进程到 WebSocket 的顺序和去重。
3. 重试和取消可能产生晚到结果；执行事件和终结状态都受尝试令牌及当前状态约束，旧令牌不能写入或完成新尝试。
4. 独立进程丢失原先内存会话；从成功结果重建用户/助手消息，并兼容旧版已完成历史，不声称恢复 Agent 检查点。
5. 自动重试不应显示成多个用户问题，人工重试不能覆盖原失败轮次；区分 task_queued、task_running、task_retrying，前端按 job_id 绑定轮次。
6. 首次租约过期测试将领取时间设在入队之前，实际无法领取；修正测试时间，使入队先于领取，再测试真实过期，而非改动生产逻辑绕过检查。

## 验证和限制

50 项后端测试全部通过，使用临时 SQLite 和实际子进程测试正常执行、崩溃后重试、超时终止、取消、进程重启保留、用户权限和旧令牌拒绝，不调用外部模型。还验证了自动 worker 真正启动、被杀后自动重启、API 退出后停止，以及独立进程事件经 WebSocket 有序送达且不重复。

前端历史恢复与滚动回归通过，TypeScript 和生产构建通过；worker 命令行入口及 `uv lock --check` 通过。新增 18 项后端队列相关测试，原有测试按入队语义更新，并非使用真实付费模型完成研究任务。

恢复从任务开头重新执行，可能重复搜索、模型计费或文件写入；不保证恰好一次。适用于同机本地磁盘，不支持多机器共享 SQLite。旧版无队列记录的进行中任务仍无法恢复。真实模型长任务、整机断电和浏览器交互尚需部署环境验收。
